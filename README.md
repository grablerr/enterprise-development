# Лабораторные работы 2 и 3: REST API и ORM для риэлторского агентства

## Общее описание

В рамках 2-й и 3-й лабораторных работ был реализован сервер на `ASP.NET Core` для предметной области риэлторское агентство. Приложение с самого начала использует полноценное хранение данных в реляционной базе (MySQL) с помощью Entity Framework Core. Хранение в памяти (In-Memory) не применялось. Все данные, контроллеры и сервисы сразу интегрированы с базой данных и репозиториями.


## Лабораторная работа 2: Сервер с REST API

### Основные задачи и подход

- Реализованы CRUD-операции для сущностей: объекты недвижимости (`RealEstate`), контрагенты (`Counterparty`), заявки (`Application`).
- Реализовано RESTful API для работы с этими сущностями через отдельные контроллеры.
- В API реализованы аналитические запросы:
    - Получение продавцов по периоду (GetSellersByPeriod)
    - Топ-5 клиентов по количеству заявок (GetTop5ClientsByRequests)
    - Количество заявок по типу недвижимости (GetRequestCountByObjectType)
    - Клиенты с минимальной ценой заявок (GetClientsWithMinPriceRequests)
    - Клиенты по типу объекта (GetClientsByEstateType)
- Вся работа с данными — через Entity Framework Core, миграции и реальные таблицы.


## Лабораторная работа 3: ORM, миграции, автосидирование

### Основные изменения и дополнения

- Настроена полноценная ORM-модель с помощью Entity Framework Core.
- Добавлены и применены миграции для создания всех таблиц и связей в базе данных.
- Разработан механизм первичного наполнения (сидирования) базы — автоматическое заполнение тестовыми данными при первом запуске.
- Вся работа с сущностями, аналитикой и CRUD-операциями идет через абстракции репозиториев.
- Добавлен и настроен AutoMapper для преобразования сущностей и DTO.
- Настроен оркестратор Aspire для совместного запуска сервера и базы данных.


## Технологический стек

- .NET 7 / ASP.NET Core
- Entity Framework Core + MySQL
- Репозитории и слой инфраструктуры
- Swagger/OpenAPI для тестирования API
- AutoMapper, миграции, сидирование, unit-тесты
- Оркестратор Aspire


## Архитектура решения

- **Domain** — бизнес-модели, перечисления, абстрактные интерфейсы репозиториев
- **Infrastructure** — реализация репозиториев, контекст EF Core, миграции и сидер
- **Application** — сервисы (аналитика, мапперы, DTO)
- **API** — REST-контроллеры, endpoints, swagger


## Итоги

Сервер реализован в виде модульного и масштабируемого REST API, сразу интегрированного с базой данных через EF Core. Все бизнес- и аналитические функции вынесены в отдельный слой сервисов, основное внимание уделено качественному API и удобству написания unit-тестов.
